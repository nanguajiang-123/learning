# 线程与进程间的通信方式

## 一、线程间通信（同一进程内）

线程共享同一进程的内存空间，因此通信相对简单，但需要注意线程安全。

### 1. 共享内存（Shared Memory）
- 同一进程内的线程天然共享堆内存、全局变量等
- 最直接高效，但需要同步机制防止竞争条件
- **示例（Java）**：
  ```java
  // 多线程共享同一个对象
  class SharedResource {
      private int count = 0;
      public synchronized void increment() { count++; }
      public int getCount() { return count; }
  }
  ```

### 2. 互斥锁（Mutex / synchronized）
- 保证同一时刻只有一个线程访问临界区
- Java: `synchronized` 关键字 / `ReentrantLock`
- C++: `std::mutex`
- Python: `threading.Lock()`

### 3. 信号量（Semaphore）
- 控制同时访问资源的线程数量
- 二进制信号量等价于互斥锁
- 计数信号量可允许多个线程并发访问
  ```python
  import threading
  sem = threading.Semaphore(3)  # 最多允许 3 个线程同时访问
  ```

### 4. 条件变量（Condition Variable）
- 用于线程等待某个条件满足时再继续执行
- Java: `wait()` / `notify()` / `notifyAll()`
- C++: `std::condition_variable`
  ```java
  synchronized (lock) {
      while (!condition) lock.wait();
      // 条件满足后执行
      lock.notifyAll();
  }
  ```

### 5. 阻塞队列（BlockingQueue）
- 生产者-消费者模式的经典实现
- Java: `LinkedBlockingQueue`、`ArrayBlockingQueue`
- 线程安全，满时阻塞生产者，空时阻塞消费者

### 6. 管道（Pipe）
- 线程间单向数据流通信
- Java: `PipedInputStream` / `PipedOutputStream`

### 7. Future / Promise
- 异步计算结果的占位符
- Java: `Future`、`CompletableFuture`
- JavaScript: `Promise`

## 二、进程间通信（IPC，Inter-Process Communication）

进程拥有独立的内存空间，通信需要借助操作系统提供的机制。

### 1. 管道（Pipe）
- **匿名管道**：只能用于父子进程之间，单向通信
- **命名管道（FIFO）**：可用于无关进程，有名字，存在于文件系统中
  ```bash
  mkfifo /tmp/myfifo
  echo "hello" > /tmp/myfifo &
  cat /tmp/myfifo
  ```

### 2. 消息队列（Message Queue）
- 内核维护的消息链表，进程可向队列发送/接收消息
- 有消息类型，可以选择性接收
- 相较管道支持双向通信，数据有边界
- Linux: `msgget`、`msgsnd`、`msgrcv`

### 3. 共享内存（Shared Memory）
- 多个进程映射同一块物理内存
- **最快的 IPC 方式**，无需内核介入数据拷贝
- 需配合信号量或互斥锁同步
- Linux: `shmget`、`shmat`、`shmdt`

### 4. 信号量（Semaphore）
- 主要用于进程间同步，而非数据传输
- System V 信号量 / POSIX 信号量
- 常与共享内存配合使用

### 5. 信号（Signal）
- 轻量级的异步通知机制
- 只能传递信号编号，不携带数据
- 常见信号：`SIGINT`（Ctrl+C）、`SIGTERM`（终止）、`SIGKILL`（强制杀死）
  ```bash
  kill -SIGTERM <pid>
  ```

### 6. 套接字（Socket）
- **最通用**的 IPC 方式，既支持本机进程间通信，也支持网络进程间通信
- **Unix Domain Socket**：本机进程间通信，性能优于 TCP
- **TCP/UDP Socket**：跨主机通信
  ```python
  # Unix Domain Socket 示例
  import socket
  sock = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
  sock.connect('/tmp/my.sock')
  ```

### 7. 内存映射文件（mmap）
- 将文件映射到进程地址空间，多个进程可映射同一文件实现共享
- Linux: `mmap()` 系统调用
- 兼具文件持久化和共享内存的优点

### 8. RPC（远程过程调用）
- 让进程像调用本地函数一样调用另一进程的函数
- 常见实现：gRPC、Thrift、XML-RPC
- 底层通常基于 Socket 通信

### 9. 消息中间件
- 适用于分布式系统的进程间通信
- 常见工具：**Kafka**、**RabbitMQ**、**Redis Pub/Sub**
- 解耦生产者与消费者，支持异步、持久化

---

## 三、对比总结

| 通信方式 | 适用范围 | 速度 | 特点 |
|---------|---------|------|------|
| 共享内存 | 线程 / 进程 | 极快 | 需同步机制 |
| 互斥锁/信号量 | 线程 / 进程 | — | 同步控制 |
| 管道 | 线程 / 进程 | 较快 | 单向，有序 |
| 消息队列 | 进程 | 较快 | 有边界，可选类型 |
| 信号 | 进程 | 快 | 仅通知，无数据 |
| Socket | 进程 / 网络 | 较慢 | 最通用，跨主机 |
| mmap | 进程 | 快 | 兼具持久化 |
| RPC / 中间件 | 分布式 | 慢 | 解耦，高可用 |

---

## 四、选型建议

- **同进程线程间**：优先用**共享内存 + 锁**，或**阻塞队列**（生产消费模型）
- **同主机进程间**：优先用**共享内存**（高性能）或 **Unix Domain Socket**（通用）
- **跨主机进程间**：使用 **TCP Socket** 或 **消息中间件**（Kafka / RabbitMQ）
- **需要解耦 & 异步**：使用**消息队列 / 消息中间件**
