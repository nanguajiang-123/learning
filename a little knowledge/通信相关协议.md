# 通信相关协议知识总结

## 一、TCP（传输控制协议）

### 概述
- **全称**：Transmission Control Protocol（传输控制协议）
- **OSI分层**：传输层（第4层）
- **连接方式**：面向连接
- **可靠性**：可靠传输，保证数据有序且完整到达
- **传输方式**：字节流

### 特点
- 建立连接需要三次握手（SYN、SYN-ACK、ACK）
- 断开连接需要四次挥手
- 有流量控制和拥塞控制机制
- 每条连接消耗资源较多
- 速度相对较慢但可靠

### 使用场景
- 文件传输（FTP）
- 电子邮件（SMTP、POP3、IMAP）
- 远程登录（SSH、Telnet）
- Web服务（HTTP/HTTPS）
- 数据库连接
- 对数据准确性要求高的应用

---

## 二、UDP（用户数据报协议）

### 概述
- **全称**：User Datagram Protocol（用户数据报协议）
- **OSI分层**：传输层（第4层）
- **连接方式**：无连接
- **可靠性**：不可靠传输，不保证数据到达和顺序
- **传输方式**：数据报

### 特点
- 无需建立连接，直接发送数据
- 速度快，开销小
- 允许广播和多播
- 数据包独立处理，可能乱序或丢失
- 每条消息大小限制（通常65535字节）

### 使用场景
- 实时视频/音频流传输
- 在线游戏
- DNS查询
- VoIP（网络电话）
- IoT数据传输
- 对实时性要求高、容错能力强的应用

---

## 三、HTTP（超文本传输协议）

### 概述
- **全称**：HyperText Transfer Protocol（超文本传输协议）
- **OSI分层**：应用层（第7层）
- **基于**：TCP协议
- **默认端口**：80
- **请求-响应模型**：客户端请求，服务器响应

### 特点
- 无状态协议（每次请求独立，服务器不保存客户端信息）
- 支持多种请求方法（GET、POST、PUT、DELETE等）
- HTTP/1.1支持持久连接（Keep-Alive）
- HTTP/2支持多路复用
- HTTP/3基于QUIC协议

### 使用场景
- 网页浏览
- RESTful API调用
- 资源获取（图片、视频、文档等）
- Web应用交互

### 主要版本
| 版本 | 特点 | 发布时间 |
|------|------|--------|
| HTTP/1.0 | 每次连接只处理一个请求 | 1996年 |
| HTTP/1.1 | 支持持久连接、管道化 | 1997年 |
| HTTP/2 | 多路复用、头部压缩、服务器推送 | 2015年 |
| HTTP/3 | 基于QUIC、更快的连接建立 | 2022年 |

## 四、HTTPS（安全超文本传输协议）

### 概述
- **全称**：HyperText Transfer Protocol Secure（安全超文本传输协议）
- **OSI分层**：应用层（第7层）
- **基于**：TCP + TLS/SSL协议
- **默认端口**：443
- **加密**：对所有数据进行加密传输

### 特点
- HTTP + SSL/TLS加密层
- 需要证书验证身份
- 建立连接需要TLS握手，增加开销
- 提高安全性但性能略低于HTTP
- 防止中间人攻击

### 使用场景
- 涉及敏感信息的网站（银行、支付、登录）
- 所有现代网站（HTTPS已成为标准）
- 需要身份认证的API
- 政府、金融等安全要求高的应用

### TLS/SSL握手过程
1. 客户端发送Client Hello
2. 服务器响应Server Hello和证书
3. 客户端验证证书并生成预主密钥
4. 两端交换密钥，建立加密通道
5. 开始加密通信

## 五、SSE（服务器发送事件）

### 概述
- **全称**：Server-Sent Events（服务器发送事件）
- **OSI分层**：应用层（第7层）
- **基于**：HTTP协议
- **通信方式**：单向服务器推送
- **连接**：长连接

### 特点
- 客户端建立一次连接，服务器主动推送数据
- 基于文本，MIME类型为text/event-stream，大语言模型流式输出
- 自动重连机制
- 只支持UTF-8编码
- 简单易用，无需复杂协议

### 使用场景
- 实时通知推送
- 股票行情更新
- 系统日志实时输出
- 进度条更新
- 聊天系统消息推送
- 单向推送且不需要低延迟场景

### 消息格式
```
data: 消息内容\n\n
event: 事件类型\n
data: 消息内容\n\n
id: 消息ID\n
retry: 重连时间\n
```

### 优缺点
| 优点 | 缺点 |
|------|------|
| 实现简单 | 只支持文本 |
| 自动重连 | 单向通信 |
| HTTP协议基础 | 连接数量受限 |
| 轻量级 | 浏览器兼容性问题 |

## 六、WebSocket

### 概述
- **全称**：WebSocket协议
- **OSI分层**：应用层（第7层）
- **基于**：TCP协议
- **默认端口**：80（ws://）或 443（wss://）
- **通信方式**：双向全双工通信

### 特点
- 客户端和服务器都可以主动发送数据
- 减少通信延迟和服务器负担
- 通过HTTP升级机制建立连接（握手）
- 长连接，数据帧格式清晰
- 支持二进制和文本数据
- 低延迟、低开销

### 使用场景
- 实时聊天应用
- 在线协作工具（Google Docs、Figma等）
- 实时游戏
- 实时数据仪表盘
- 股票行情实时推送
- 需要双向、高频通信的应用

### 握手过程
1. 客户端发送HTTP升级请求
2. 服务器同意升级，返回101状态码
3. 连接升级为WebSocket
4. 开始双向通信

### 优缺点
| 优点 | 缺点 |
|------|------|
| 双向通信 | 实现相对复杂 |
| 低延迟 | 需要服务器支持 |
| 低开销 | 某些代理不支持 |
| 全双工 | 连接保持需要心跳 |

## 七、协议关系与对比

### 分层关系图
```
应用层：HTTP/HTTPS --- SSE
        WebSocket
        
传输层：TCP --- HTTP/HTTPS、WebSocket
       UDP --- 游戏、视频流
```

### 完整对比表

| 特性 | TCP | UDP | HTTP | HTTPS | SSE | WebSocket |
|------|-----|-----|------|-------|-----|-----------|
| **连接方式** | 面向连接 | 无连接 | 请求-响应 | 请求-响应 | 长连接 | 双向连接 |
| **可靠性** | 可靠 | 不可靠 | 可靠 | 可靠 | 可靠 | 可靠 |
| **通信方向** | 双向 | 双向 | 单向（客户端请求） | 单向（客户端请求） | 单向（服务器推送） | 双向 |
| **延迟** | 中等 | 低 | 中等 | 中等 | 低 | 极低 |
| **连接开销** | 中等 | 低 | 中等 | 高 | 中等 | 中等 |
| **加密支持** | 可选(TLS) | 可选(DTLS) | 不支持 | 支持(TLS) | 支持(HTTPS) | 支持(WSS) |
| **常见端口** | 多种 | 多种 | 80 | 443 | 80/443 | 80/443 |
| **适用场景** | 通用数据传输 | 实时性优先 | Web浏览 | 安全Web | 服务推送 | 实时交互 |

### 应用场景选择流程图
```
需要通信
   ↓
是否需要可靠传输？
   ├─ 否 → 使用UDP
   └─ 是 → 继续
     ↓
   在Web中使用？
     ├─ 否 → 使用TCP
     └─ 是 → 继续
       ↓
     需要双向实时通信？
       ├─ 否 → HTTP/HTTPS或SSE
       │      ├─ 需要推送？ 是 → SSE
       │      └─ 需要推送？ 否 → HTTP/HTTPS
       └─ 是 → WebSocket
         ↓
       需要加密？
         ├─ 是 → HTTPS或WSS
         └─ 否 → HTTP或WS
```
